SLIDE 8 — PROPOSED OVERALL ARCHITECTURE
========================================================
1. Slide Title: Proposed Overall Architecture
2. Main Content: Multi-tier secure architecture of Trustline.
3. Bullet Points:
   - Frontend: React 19 wrapped in Tauri v2 for native desktop performance.
   - Crypto Layer: Rust IPC handling cryptographic operations locally (Argon2id, AES-256-GCM).
   - Local Storage: SQLCipher providing a highly secure, encrypted local database vault.
   - Backend Relay: Rust (Axum/Tokio) functioning as a strictly stateless, blind routing engine.
   - Database Isolation: PostgreSQL with Row-Level Security (RLS) for tenant separation.
   - Message Broker: NATS JetStream for high-throughput encrypted packet routing.
7. Diagram Explanation: Data remains encrypted from the React UI, passes through the Rust crypto boundary, and is blindly relayed by the backend to the recipient's secure workspace.

========================================================
SLIDE 10 — MODULE 1 CONTINUED
========================================================
1. Slide Title: Module 1 - Double Ratchet Protocol
2. Main Content: Continuous security for ongoing communication sessions.
3. Bullet Points:
   - Root Chain Synchronization: Orchestrating the derivation of all subsequent key chains.
   - Sending/Receiving Chains: Independent key rotation for inbound and outbound message flows.
   - Message Key Derivation: Every single message is encrypted with a unique, one-time key.
   - Forward Secrecy: Compromised current keys cannot decrypt previously sent messages.
   - Post-Compromise Security: A compromised session heals itself upon the next asynchronous key exchange.
6. Technical Notes: The Double Ratchet algorithm combines cryptographic ratchets (KDF chains) and public-key ratchets to ensure extreme session durability.

========================================================
SLIDE 11 — MODULE 2
========================================================
1. Slide Title: Module 2 - Blind Router Backend
2. Main Content: A server that routes, but cannot read.
3. Bullet Points:
   - Axum/Tokio Backend: High-concurrency Rust server handling thousands of parallel connections.
   - Encrypted WebSocket Relay: Providing the real-time transport layer for E2EE blobs.
   - Stateless Routing: The server holds no decryption keys and maintains no plaintext message state.
   - Zero Plaintext Visibility: Eliminating the risk of backend database breaches exposing user chat history.
   - Packet Forwarding Workflow: Routing via NATS JetStream based on ephemeral metadata identifiers.
6. Technical Notes: The backend acts merely as a post office moving locked briefcases without the ability to open them.
