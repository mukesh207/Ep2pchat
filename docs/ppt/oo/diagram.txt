## **1. Zero-Knowledge "Blind Router" Logic**
This diagram illustrates the "Cryptographic Barrier." Plaintext exists only in the volatile memory of the client's device, while the server only ever handles "locked" data.

```text
[ CLIENT DEVICE (Secure) ]             [ UNTRUSTED NETWORK ]            [ BACKEND (Blind) ]
+-----------------------+              +-------------------+            +-----------------+
|  User Interface (UI)  |              |                   |            |  Rust / Axum    |
|       (React)         |              |                   |            |  Relay Server   |
+-----------+-----------+              |                   |            +--------+--------+
            |                          |                   |                     |
+-----------v-----------+              |                   |            +--------v--------+
|  Tauri Rust Runtime   |              |                   |            | NATS JetStream  |
| (Crypto Operations)   |              |                   |            | (Msg Routing)   |
+-----------+-----------+              |                   |            +--------+--------+
            |                          |                   |                     |
+-----------v-----------+      (Encrypted Blobs)           |            +--------v--------+
|   SQLCipher Vault     | <===========================================> | PostgreSQL DB   |
| (Local Decrypted DB)  |              |                   |            | (RLS Isolated)  |
+-----------------------+              +-------------------+            +-----------------+
```

## **2. X3DH Key Agreement (Asynchronous Setup)**
This depicts how Alice derives a shared secret to message Bob even if he is currently offline.

```text
  ALICE (SENDER)                    TRUSTLINE SERVER                    BOB (RECIPIENT)
  +------------+                    +--------------+                    +-------------+
        |                                   |                                  |
        |                                   | <--- [1. Upload Pre-Keys] -------|
        |                                   |      (IK_b, SPK_b, OPKs)         |
        |                                   |                                  |
        | --- [2. Fetch Bob's Keys] ------> |                                  |
        | <--- (IK_b, SPK_b, OPK_b1) ------ |                                  |
        |                                   |                                  |
  [3. LOCAL MATH]                           |                                  |
  Generate EK_a                             |                                  |
  DH1 = (IK_a, SPK_b)                       |                                  |
  DH2 = (EK_a, IK_b)                        |                                  |
  DH3 = (EK_a, SPK_b)                       |                                  |
  DH4 = (EK_a, OPK_b1)                      |                                  |
  SECRET = HKDF(DH1-4)                      |                                  |
        |                                   |                                  |
        | --- [4. Encrypted Msg] ---------> |                                  |
        |      (Ciphertext + EK_a)          | --- [5. Blind Route] ----------> |
        |                                   |                                  |
        |                                   |                          [6. LOCAL MATH]
        |                                   |                          Derive SAME Secret
        |                                   |                          Decrypt & Sync
```

## **3. The Double Ratchet Protocol**
This shows the "self-healing" nature of the encryption. Every message advances the chain so that a single compromised key does not expose past or future messages.

```text
    [ ROOT CHAIN ]
          |
    +-----+-----+
    |  DH STEP  | (New DH exchange per round-trip)
    +-----+-----+
          |
          +-------------------------------------------+
          |                                           |
  [ SENDING CHAIN ]                           [ RECEIVING CHAIN ]
          |                                           |
  +-------v-------+                           +-------v-------+
  | KDF-SEND (n)  |                           | KDF-RECV (m)  |
  +-------+-------+                           +-------+-------+
          |                                           |
  +-------v-------+                           +-------v-------+
  |  MESSAGE KEY  |                           |  MESSAGE KEY  |
  | (One-Time)    |                           | (One-Time)    |
  +---------------+                           +---------------+
```

## **4. WebAuthn Passwordless Authentication**
Trustline anchors identity to hardware biometrics (Touch ID, Windows Hello, or Security Keys) rather than vulnerable passwords.

```text
   USER DEVICE (Hardware)               TRUSTLINE BACKEND
   +--------------------+               +-------------------+
   |  Browser/Tauri UI  |               |   webauthn-rs     |
   +---------+----------+               +---------+---------+
             |                                    |
             | <------- [1. Challenge] -----------|
             |                                    |
   +---------v----------+                         |
   |   SECURE ENCLAVE   |                         |
   | (Biometric Check)  |                         |
   +---------+----------+                         |
             |                                    |
             | -------- [2. Signed Auth] -------->|
             |                                    |
             |                                [3. VERIFY]
             | <------- [4. JWT Issued] ----------|
```

## **5. PostgreSQL Row-Level Security (RLS)**
Isolation is enforced at the database layer. This ensures that a bug in the application code cannot bypass tenant boundaries.

```text
     [ INCOMING QUERY ]
             |
   +---------v----------+
   |   SET LOCAL       |
   | app.current_org_id| <--- (Assigned per session/request)
   +---------+----------+
             |
   +---------v----------+
   |  POSTGRES ENGINE   |
   | (RLS Enforcement)  |
   +---------+----------+
             |
    _________v_________________________________
   | DATABASE ROWS                             |
   | [Org A Data] <--- [ ACCESS GRANTED ]      |
   | [Org B Data] <--- [ ACCESS DENIED ]       |
   |___________________________________________|
```
