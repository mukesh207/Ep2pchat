# ADR-001: Zero-Knowledge Blind Router Architecture

**Status:** Accepted  
**Date:** 2026-03-15  
**Authors:** Trustline Engineering

## Context

Enterprise messaging platforms must guarantee that the hosting provider cannot read customer communications. Traditional architectures terminate TLS at the server and have full access to message plaintext. Regulatory requirements (GDPR, HIPAA) and enterprise security policies increasingly demand server-side zero-knowledge guarantees.

## Decision

The Trustline backend operates strictly as a **blind router**:

1. **All cryptographic operations** (key generation, X3DH handshake, Double Ratchet encryption/decryption) execute **client-side** inside the Tauri Rust runtime via IPC commands.
2. The backend receives only **encrypted blobs** (`ciphertext` + `ratchet_header`) and a `recipient_device_id` — it has no access to plaintext or private keys.
3. Private keys are stored in the device's **OS Secure Enclave** (via `keyring` crate) or an **encrypted SQLite vault** (SQLCipher) — they never leave the device.
4. The Rust `crypto_core` crate is shared between the Tauri client and used as a library — the backend does **not** link to it for message operations, only for OTPK validation.

## Consequences

- **Positive:** The server operator (or an attacker who compromises the server) cannot read any messages.
- **Positive:** Compliance with zero-knowledge data sovereignty requirements.
- **Negative:** Server-side search is impossible — full-text search must be done locally (solved via FTS5 on the client vault).
- **Negative:** Message recovery after device loss requires the user to have registered another device before loss occurs.
